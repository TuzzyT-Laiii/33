# TRN作业与GPU功率对应证据

本轮输入为PR [#36](https://github.com/TuzzyT-Laiii/33/pull/36)的`1594fb7`。新增Seren集群条件反推、MIT官方DNN标签的作业监测分析、公开资料核查，以及H100受控训练实验的直接统计。当前正文的0.80中央值、Kalos日形状及其小时结果保持原值；所有新方案只在本报告的对比表中计算。

可直接对应的证据包括MIT官方DNN作业与GPU监测，以及公开H100实验设置与八卡功率。PM100提供生产HPC作业与整机功率对应。Seren支持长窗口集群条件反推，仍缺少逐作业到设备的映射。完整来源、时间、粒度、映射、硬件、大小及许可见[12项资料登记表](public-source-register.csv)，按目标量接近程度排列的数值见[TRN功率证据表](trn-power-evidence.csv)。

## Seren：93.59天重叠及集群条件反推

官方`trace_seren.csv`实际为818,327行，其中450,590个GPU作业；作业执行范围为UTC 2023-02-28 16:18:54至2023-08-22 07:01:59。GPU作业起止区间有效，原始`duration`与执行时长一致。字段包括`job_id`、`node_num`、`gpu_num`、`type`及时间；`node_num`仅表示数量，没有节点列表、GPU设备标识或作业设备映射。

Seren监测覆盖UTC **2023-05-16 09:43:15至2023-08-18 00:00:00**，完全处于作业窗口之内，日历重叠**93.59497天**，实际采样**2,243.62083小时**。功率与利用率原件共10,884,358,479字节，沿用服务器已有文件并核对SHA-256。原始文件大小见[来源体积](source-file-sizes.json)。

物理库存按Acme论文采用2,288张A100-SXM 80GB，每卡TDP 400W；发布表为1,992个设备列。功率报送覆盖物理库存的均值为**83.2225%**，小时范围74.2570%—86.6171%；按发布设备列计算的总体有效率为95.5889%。报送数量无法确认在线库存，两个指标的配对有效时间单独保存。

逐采样时刻根据全部GPU作业的`[start_time,end_time)`重建分配数。反推采用

`P_est(t)=有效报送设备平均功率(t)×2,288`

`p_alloc(t)=[P_est(t)−(2,288−N_alloc(t))×P_idle]/N_alloc(t)`。

这里将全部物理库存视为在线，并假设缺测设备可由报送设备代表。该假设支持条件估计，在线状态与缺测设备的真实分配构成仍未知。小时量按相同采样时刻积分，时间缺口不延续前值。

中央空闲采用60W；同设备同时间且GPU利用率为零的功率代理为**67.300W**。该代理可能包含已分配等待状态，未宣称其为已证实的未分配状态。筛选功率报送覆盖至少80%、小时采样至少95%、分配量为正且未超过库存后，得到**2,057个小时分组**，约2,056.967个采样小时。

| 统计口径 | 已分配GPU功率/TDP |
| --- | ---: |
| GPU小时加权均值 | 0.7623 |
| GPU小时加权P10 / 中位数 / P90 | 0.6139 / 0.7683 / 0.8963 |
| 小时范围 | 0.3091—1.0624 |
| 空闲50W / 70W对应均值 | 0.7807 / 0.7439 |
| 空闲采用零利用率代理对应均值 | 0.7489 |
| 缺测设备各按60W / 400W估计对应均值 | 0.6608 / 0.9028 |

有8个小时超过额定TDP，没有负值，全部保留诊断标记。额定TDP不构成严格的瞬时仪表上限。另给出0—1范围子集：2,049小时、均值0.7617。缺测设备60W和400W是工程端点，未解释为置信区间或严格物理边界。[完整反推敏感性](seren/seren-inverse-sensitivity.csv)保留各口径。

合格期预训练占分配GPU小时的**53.44%**。有27个小时的预训练占比至少80%，这些混合时段的估计均值为**0.7828**，P10/中位数/P90为0.7021/0.7838/0.8392。预训练占比至少90%的合格小时为零；各类型纯运行小时也为零。SFT、评估等功率无法独立分解，任务类型主导分组仅代表混合功率的条件统计，见[类型构成表](seren/seren-type-dominance.csv)。

估计比例按UTC小时汇总的日内最高/最低为**1.0310**，最低UTC12时、最高22时。它包含任务构成、分配与缺测代表性影响，不能识别预训练专属的自然日周期，也不能归因于检查点或同步等待。原始字段、配对覆盖及逐小时分配见`seren/`。

## MIT：官方标签与作业功率直接对应

只读使用`D:\mit-supercloud-gpu-summary-20261028`。采用一次冻结的**3,037个不可变批次**快照，而非仅依赖较早的`existing-job-telemetry.parquet`。原始标签CSV实际包含**3,430个唯一作业**；来源README的文字数量为3,425，本次按CSV原件统计。

关联链为官方`id_job`→按作业/节点命名的监测对象→GPU索引。仅采用`schema_version=2`、设备可归属、请求与分配有效的V100文件，并截取分配区间内数据。沿用已有以Slurm epoch审计的纽约墙上时间校正；未另行拟合时差。设备歧义、暂停和DST边界状态不混入合格对象。

快照共有14,247个文件，合格V100监测覆盖**13,431个作业**，其中**1,393个官方DNN标签作业**，约占全部标签的40.61%。1,305个标注作业的观测GPU时间达到分配GPU时间的80%以上。原始100ms级记录已在既有批次内汇总为小时矩及5W功率直方图，本轮复用这些不可变结果。

快照的可归属文件覆盖2021-02-09至10-01，官方DNN文件覆盖2021-05-07至09-28；这些日期是文件观测范围，未表示中间全部日期、作业和设备已完整覆盖。

| 组别 | 作业数 | 实测GPU时间，小时 | GPU时间加权W/张 | 功率/TDP，250W参考 | 覆盖至少80%后的比例 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全部已观测V100 | 13,431 | 320,065.63 | 97.35 | 0.3894 | 0.3878 |
| 官方DNN训练 | 1,393 | 12,345.66 | 170.47 | 0.6819 | 0.6878 |

| GNN | 27 | 46.71 | 67.82 | 0.2713 | 0.4077，仅2个合格作业 |

官方DNN的设备时间功率/TDP P10/中位数/P90为**0.23/0.79/0.97**，全部V100为0.15/0.23/0.81。分位数来自5W直方图中点，比例分辨率为0.02，且要求功率与利用率联合有效；均值则采用全部有效功率时间。作业等权均值、作业均值分位数与GPU时间加权统计分别保存，未混用统计单位。

覆盖合格的DNN作业中，功率变异系数中位数为**0.2723**，全部合格V100作业为0.2314；该指标包含时间波动和卡间差异。673个DNN作业具有至少四个小时分组；5,103对相邻小时的绝对功率变化/TDP中位数为**0.00271**、P90为**0.02338**。小时均值平滑了短时变化，这些数值不能替代100ms波动幅度。BERT类微调没有满足四小时分组要求的作业，未外推其长程形状。

官方DNN按纽约当地小时条件汇总的日内比为**1.0722**，全部已观测V100为1.0316；对每个DNN作业先除以自身均值后为1.0673。BERT类微调原始日内比1.6266，按作业标准化后1.1101，显示业务/作业构成会显著影响日形状。这些结果是观测条件统计，未识别LLM预训练固定日周期。

按对象键核对全部标签库存后，尚缺**8,357份文件，47,886,634,172字节（47.89GB）**，涉及2,124个需要补充文件的作业；其中部分已有不完整监测。全部标签文件约68.78GB。缺口超过用户30GB限额，**没有追加下载MIT监测**。官方标签包括CNN、GNN及BERT微调，不构成现代大规模LLM预训练样本。

详细分组、模型、日形状、作业内进度和覆盖敏感性见`mit/`。作业级、设备级及缺失对象计划保留在本机已忽略的处理目录。没有修改MIT源目录、流式进程或STOP文件。

## H100公开实验：训练设置与逐GPU功率直接对应

检索取得[Scientific Data 2026论文](https://doi.org/10.1038/s41597-026-07496-6)及[Figshare v1数据](https://doi.org/10.6084/m9.figshare.31654879.v1)。压缩包**209,685,111字节**，MD5与发布值一致，并记录SHA-256。数据含H100/B200节点32个会话和RTX3060单机40个会话；节点每个记录窗口15分钟、轮询20ms，实际仪表更新受NVIDIA驱动频率约束。

H100 LLM目录有12条CSV路径，三份为完全相同的基准副本；按解压后SHA-256去重为**9个独立窗口**、8,099.82秒，合计约**2.25小时**。每个窗口对应一组LLaMA 1B/3B/8B、batch、序列长度和DeepSpeed设置，并包含8个GPU的W字段。H100为SXM 80GB，按700W归一化。训练使用LLaMA-Factory；预训练或SFT阶段、录制窗口占完整作业的比例及时间的时区尚未声明。

| H100实验设置 | 记录窗口均值GPU/TDP |
| --- | ---: |
| 8B、长度2048、ZeRO3、batch16 | 0.7555 |
| 同设置、batch2 / batch32 | 0.3817 / 0.7898 |
| 同设置、ZeRO1 / ZeRO2 | 0.7045 / 0.7354 |
| 1B / 3B、长度2048、ZeRO3、batch16 | 0.4732 / 0.6279 |
| 8B、长度1024 / 4096、ZeRO3、batch16 | 0.7552 / 0.7534 |

九个设置的GPU时间加权均值为**0.6641**。该均值由实验设计决定，不作为生产预训练的总体估计。单次记录内GPU利用率均值约57.8%—85.8%；功率与利用率之间没有强制线性换算。

W字段与发布的功率百分比字段有少量不一致，各窗口约0.0158%—0.1469%的设备样本；原因未核实。本次以原始W字段除以700W，保留差异标记及超过额定功率的观测。没有从短窗口构造24小时或星期规律。每段约45秒的窗口进度汇总及分位数见`h100-experiments/`。

许可信息存在差异：Figshare元数据标为**CC BY 4.0**，压缩包README和LICENSE明确为**CC BY-NC-ND 4.0**；论文采用后者。本仓库只保存统计事实、图和审计元数据，原始压缩包留在本机，不重新分发。

## 正文建议及报告内对比

**建议正文保留已分配GPU功率/TDP中央值0.80，以原生资源分配产生小时变化；额外固定日因子放入敏感性。** 0.80仍是H100大模型训练情境参数，未声称由公开生产预训练逐作业功率标定。OLMo活跃阶段、H100大batch实验及Seren预训练主导混合时段支持其数量级；GPU实现、batch、通信和等待状态仍带来明显差异。

水平敏感性保留**0.65/0.95**。若TRN包含小batch开发训练，可另用**0.40**作为扩展低端；该端点来自特定受控设置，不作为全部预训练的下界。形状敏感性采用**无额外日因子、Seren相对日形状、现有Kalos相对日形状**。这些都是工程假设，未解释为置信区间。

报告内使用相同90天需求、天气、CPU、空闲及设备数量比较下列方案。三个0.80方案的GPU小时加权均值相同；窗口平均IT因而相同。下表为10MW参考规模，全部四档、IT及设施指标见[72行方案对比](proposal-comparison.csv)。

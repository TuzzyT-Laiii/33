# 按原生经过时间约束的柔性成本结果

本工作包比较规划阶段重新优化能源资产和已建成阶段固定能源资产两种边界，覆盖八城市、全部 11 个 CPU/GPU 情境、六档电量匹配目标与既有卡价扫描。相同服务量、天气、电价和成本参数采用 `flex-card-cost-20261102` 对应输入；任务到期按来源保留的真实小时间距判断。

## 输入与时间边界

训练需求沿用 Seren 正文窗口的 2,057 个观测小时。窗口内有 53 处时间缺口，共 189 个未观测小时。模型只在实际保留的小时建立执行变量；到期早于下一可观测小时的任务必须在缺口之前完成。缺口未补造负荷、气象或发电值。

统一执行时钟使用 `source_hour_index`。八份 HPC 输入的 `time_utc` 是气象年份映射，跨年回退不改变来源连续时长；原始日期无时区信息，绝对 UTC 时刻属于映射假设。其余 80 份输入的 UTC 间距与来源小时轴完全一致。全部 88 份输入的时钟审查和 528 组期限约束数组等价验证见[容量审查目录](../existing-compute-capacity-20261102/README.md)。

可推迟·整体与可推迟·可拆分分别采用 12 和 48 个经过小时的研究情境期限，窗口末清空积压。两类任务均采用小时工作量变量；整体作业开始后不可中断、逐卡资源分配、显存和并行拓扑尚未建模。

## 计算与验收范围

- 训练重算覆盖规划 864 例、固定能源资产 432 例，共 1,296 个唯一组合。输入、小时结果和摘要由 `hourly-index.csv` 逐例关联并记录 SHA-256。
- 非训练规划 2,304 行及固定能源资产 1,152 行保留原结果；发布程序逐字段核对其数值完全相同。连续来源的期限约束与既有连续小时算法等价，因此不重复求解这些情境。
- 独立 FIFO 分配从真实到达量和执行量核对最长时延、提前执行、未服务量、服务量守恒与累计积压，同时核对任务功率容量、设施功率、供需平衡和窗口 CFE 电量。绝对门槛为 0.0001 MW 或 MWh。详细结果为 `independent-dispatch-audit.json`。
- 53 个固定能源资产案例采用 COPT 交叉恢复重新求解，`FeasTol=DualTol=1e-9`、`Crossover=1`。其他 1,243 例保留已经独立验收的小时输出，结合案例键、索引及输入输出指纹复用审查证据。不同求解版本分别留存，不改写既有输出。
- `economic-consistency-audit.json` 核对完整训练组合、有限成本和装机、无柔性成本一致、期限收紧后的成本方向，以及柔性解不劣于同参数无柔性解。固定无柔性基线复用同参数规划最优点时，逐项资产完全相同，并保留来源小时输出指纹。

全部情境的汇总状态、有效配对及保存残差另在容量审查中报告。非训练行沿用既有验证范围，未纳入本次训练逐时独立验收。

## 成本和容量口径

无柔性机群按观测窗口动态任务功率峰值 K 配置，每小时执行功率受 K 加新增容量约束。新增容量是功率代理，不能直接视为已核实可分配的 GPU 卡数。零新增容量与正移位量的配对结果见[既有算力容量分析](../existing-compute-capacity-20261102/README.md)。

规划阶段允许风光储和市电接入容量重新优化；已建成阶段将这些资产固定为同参数无柔性最优配置。后者的储能资本已经发生，调度收益主要反映窗口运行费用变化。卡价、设备寿命、全时待机和任务权限沿用研究情境参数，未经现场报价或实际服务承诺验证。

成本百分比以能源系统加新增算力成本为分母，既有机群资本未计入；绝对差额仍比较相同计算服务。alpha 约束为逐小时供能后汇总的窗口电量匹配率 `Σ市电 ≤ (1−alpha)×Σ设施用电`。95% 目标不要求每个小时达到 95%。金额按原生观测小时折算的“等效年化”只用于同口径比较，未构造完整年度任务序列。

## 文件与复现

`runs-cards.csv` 和 `runs-fixed.csv` 分别保留全部 3,168 与 1,584 个组合；非最优状态继续保留在原组合位置，统计仅采用有效配对。`delivery-manifest.json` 记录新旧摘要指纹和保留行数；`precision-provenance.json` 记录精度重算来源及模型指纹。

`run-inputs.json` 和 `seed-provenance.json` 保留对应阶段的运行配置与复用来源；它们的源码指纹描述各自运行时版本。最终模型指纹另由 `precision-provenance.json` 和期限等价报告共同核对。

`boundary-a-values.csv`、`fixed-supply-values.csv` 和 `card-unit-cost.csv` 为逐城市配对及单位成本。由报告程序生成的 `table-*.csv` 保留其既有报表结构；当前第七章的规划/已建成两张表与有效城市数由文档工作包另行生成。

完整小时文件保存在研究服务器的本任务独立目录，存放位置见 `hourly-storage.json`。索引相对路径以该文件指定的小时索引根目录解析；仓库中的索引与完整审查报告可用于按 SHA-256 校核取得的文件。

复现依次使用 `rerun_training_calendar.py` 求解训练组合，`audit_real_time_flex_dispatch.py` 独立检查小时结果，`verify_training_calendar_results.py` 验证经济一致性，最后以 `publish_training_calendar.py` 合成全部情境结果。仅需提高精度的真实案例使用 `refine_calendar_results.py`，证据合成使用 `combine_dispatch_audits.py`。相关程序均要求显式输入目录，不改写来源原文或小时文件。

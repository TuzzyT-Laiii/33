Lisa GPU 核查

只读读取官方 Slurm 压缩包和硬件表，官方 MD5 均通过。201,338 条 GPU 分区作业从 2021-12-27 16:59:32 至 2022-11-01 13:58:54，中间含 308 个完整日时间窗；可核验 GPU 卡小时的天数为 0。

作业表包含 id、submit_date、start_date、end_date、node、nodetypes、numnodes、numcores、state。没有 GPU 请求数、分配数、利用率或功率字段。GPU 分区的宿主 CPU 核心小时可计算；硬件表 210 张卡的静态库存无法确定共享分区各作业的卡数。

官方另提供 30 秒监测：prom_table_cleaned.zip 为 10,242,740,338 字节，prom_slurm_joined.zip 为 6,895,904,211 字节。本次没有下载这些监测包；现有本地 data/ 和服务器来源目录未发现 Lisa 监测原文。完整监测的 GPU 字段、有效覆盖日与联合占用仍待核验。

采用 MIT Supercloud 202201 的完整 Slurm 调度表，配套官方 TRES 映射、README、LICENSE，以及两份小型 GPU 监测 CSV。原始文件仅下载到 pku-test，本机保留审计及小时聚合输入，原始数据与逐作业处理表未提交仓库。

| 许可 | 数据 CC BY-NC-ND 4.0，采用下载对象 LICENSE；代码仓库的 MIT 许可不替代数据许可 |

官方 README 概述约 460,497 条作业、98,177 条 GPU 请求；本次对象实值为 395,914 行、98,176 条 GPU 请求。计数采用已校验下载对象，差异保留为版本质量信息。日志采集完整性和漏报率未独立证明；取消或失败作业在有效执行区间内仍有资源占用。

该样本支持科研 GPU 资源分配需求形状。Tesla/Volta 向 H100 的性能、显存适配、活跃利用率与整机功率响应待核定；分配占用不直接作为计算单元活跃利用率。本次未推定时区、服务截止期限或抢占权限。

## 文件、复现与后续边界

server-configurations.csv/json 从 20261028 版逐字段继承设备参数；scenario-matrix.csv/json 保存 52 个设计单元。每个科研 GPU 单元新增 demand_key、demand_basis、demand_observed_days、demand_observed_hours 及来源审计路径。运行功率和设备数量保持原标定状态，风冷 44 个、直接液冷 8 个。

data/metadata/research-gpu-demand-20261028/source-audit.json 保存 Lisa 字段、原文校验、MIT 下载来源与体积、请求/分配筛选、覆盖质量及独立积分检查。data/processed/research-gpu-demand-20261028/ 保存逐小时占用、同相位全年示意重放和日均表，按数据目录规则忽略。

服务器原始目录：/data3/dataset/ljt/lisa-gpu-demand-20261028/data/raw/mit-supercloud-202201

在服务器运行 acquire_research_gpu_source.py，只获取必要调度表、映射和两份小样本；再运行 audit_research_gpu_demand.py，参数分别指定 --lisa-dir、--mit-dir、--output-dir。将审计 JSON 和小时 CSV 恢复到项目 data/processed/research-gpu-demand-20261028/ 后，在项目根目录运行 python analysis/build_server_count_scenarios.py。依赖见 analysis/requirements-research-gpu-demand.txt。

独立审阅：validation.json 核验配对、标识、字段继承、CSV/JSON 一致、原文与旧结果校验和、资源小时守恒、96 次实际区间交集检查以及图表导出。manifest.json 登记输入、代码和交付物 SHA-256。PDF 每页渲染到 .codex-temp/server-count-scenarios-20261028-v2/。

后续需要核实日志漏报、时区和 CPU 调度单位，补足实际利用率及功率监测，并建立向 H100 的工作量与联合功率映射。Alibaba 2018 全表仍待完成下载核验；本次没有使用未完成输入。冷却模型由独立任务维护。

# 算力中心情境设计与负荷计算说明


算力中心情境设计

与负荷计算说明

规模 × 设备构成 × 需求导向 · 外生气象输入 · 2026 年 10 月 26 日



## 1 情境设计：每个网格、每年 36 组



| 维度 | 比较值 | 定义 |

| --- | --- | --- |

| IT 规模 S | 1、10、100、500 MW | 参考高负载 IT 预算，冷却和配套另计 |

| 数据中心模式 | CPU 主导、GPU 主导、均衡 | 按 CPU/GPU 设备池的参考 IT 容量划分 |

| 需求导向 | 科研超算、大模型开发、生产 AI 服务 | 规定业务类型、需求序列及其数据来源 |



四档规模、三种设备构成和三种需求导向交叉形成 4×3×3=36 组设计情境。每个网格、每个年份复用这套编号，输入当地气象；各组合的数据准备状态另行记录。



### 设备构成的参考配比



| 模式 | CPU 池占 IT 容量 | GPU 池占 IT 容量 |

| --- | --- | --- |

| CPU 主导 | 75% | 25% |

| GPU 主导 | 25% | 75% |

| 均衡 | 50% | 50% |



配比是研究比较点。资源占用随原任务序列变化，全年电量占比由模型计算。GPU 池按含宿主 CPU、内存等组件的整机计量；独立 CPU 池只包含另行运行的 CPU 业务。

例如：100 MW × GPU 主导 × 大模型开发，配置 25 MW CPU 池与 75 MW GPU 池，需求来自 Acme 开发作业，外部环境来自所选网格的逐小时温湿度。当前 36 组为实验设计，尚未完成其联合负荷计算。



## 2 需求从哪里来，如何形成小时曲线



| 需求导向 | 独立 CPU 池 | GPU 整机池 | 当前准备状态 |

| --- | --- | --- | --- |

| 科研超算 | Lisa CPU 分区作业 | Lisa GPU 分区及节点监测 | CPU 已累计；GPU 须补齐卡数与监测口径 |

| 大模型开发 | Acme 中 gpu_num=0 的 CPU 作业 | Acme 预训练、微调、评估与调试作业 | 两类作业已核验；容量和功率映射须保留代理说明 |

| 生产 AI 服务 | 同类业务的独立 CPU 记录，需补充 | ASI 的训练、在线/离线推理与开发 | GPU 核验一天；GPU 宿主 CPU 不充作独立 CPU 池 |



同一需求导向尽量保留同源、同时段的 CPU/GPU 关系。跨来源组合须注明业务含义和相对起点；缺少的业务记录保留为缺口。科研 CPU 加生产 GPU 可作为明确命名的组合业务情境，标为研究构造并分别注明来源。



### 按实际运行区间累计资源



对作业 i，资源数量为 n_i，运行区间为 [s_i,e_i)。时间段 h 内的资源小时为：

W<sub>h</sub> = Σ<sub>i</sub> n<sub>i</sub> × overlap_seconds([s<sub>i</sub>,e<sub>i</sub>),h) / 3600

W_h 分别以核心小时或 GPU 小时计；除以时间段小时数得到平均占用 D_h。秒级作业可累计为 5 分钟和小时；ASI 保留原生小时粒度。排队不计入执行用量，短作业不向上取整到整小时。

资源份额 u_h=D_h/K_h，其中 K_h 为同口径的源资源容量。优先采用有依据的库存；仅有观测并发峰值时，标为规模参考。ASI 用归属 GPU 小时形成 D_h，申请数量单独保存。分配或归属数量映射到节点功率时保留代理性质，超出库存的需求须核对原因。

各来源保留原有曲线形状和任务构成，平均占用自然形成。规模放大采用同形状容量外推；多集群合成时另行保留共时关系，不预设扩大规模后必然更平稳。



## 3 所有情境共用的功率计算步骤





### ① 将 IT 预算分成两个设备池



令 CPU 容量份额为 α，CPU/GPU 预算分别为 αS 和 (1−α)S。按参考整机高负载功率取整为节点：

N<sub>C</sub>=floor(10<sup>6</sup>αS / 546)；N<sub>G</sub>=floor[10<sup>6</sup>(1−α)S / 8430]

CPU 参考节点为 128 核心，空闲/高负载功率为 120/546 W；GPU 为 8×H100 整机，空闲/联合高负载为 1860/8430 W。卡数为 8N_G，CPU 池核心数为 128N_C。[4,5]



### ② 将两类资源曲线分别转换成 IT 功率



按各自实测功率点线性插值得到单节点功率 p_C(u_C,h)、p_G(u_G,h)，单位为 W。合计 IT 电功率为：

P<sub>IT,h</sub>=[N<sub>C</sub>p<sub>C</sub>(u<sub>C,h</sub>)+N<sub>G</sub>p<sub>G</sub>(u<sub>G,h</sub>)] / 10<sup>6</sup>　(MW)

现有参考算法将小时平均资源份额映射到整机功率，包含持续通电的空闲功耗。小时内部的短时尖峰会被平均，不能据此恢复分钟峰值；节点功率非线性时，小时平均映射保留近似性质。



### ③ 合并散热需求，计算共享冷却



设备散热 Q_h≈P_IT,h，单位为 MW 热。取整后的安装参考容量 C=(546N_C+8430N_G)/10<sup>6</sup>，令 q_h=P_IT,h/C。冷却和配套采用同一参考模型：

P<sub>j,h</sub>=CΣ<sub>k</sub>β<sub>k,j</sub>X<sub>k</sub>(q<sub>h</sub>,T<sub>h</sub>,Td<sub>h</sub>)

X 包括常数、q、q²、温度及露点分段项和低温响应，β 为 ESIF 的 8×4 标定系数。[6] j 为室外冷却、HVAC、泵和其他配套，前面三个分项相加为 P_cool。设施总功率 P_fac=P_IT+P_cool+P_other；共享冷却按总热负荷计算一次，散热单独保存。

各情境统一参考冷却配置，便于比较天气差异。目标设施的冷却技术、供水温度及规模效率需要对应标定；GPU 整机宿主功耗已计入，公共网络与存储按其实际边界另列。



## 4 外生输入、全年累计与结果





### 外生输入：当地逐小时温湿度



| 输入 | 单位与要求 | 进入计算的位置 |

| --- | --- | --- |

| 网格、年份、UTC 小时 | 平年 8760、闰年 8784 小时；无重复或缺口 | 连接需求重放与当地气象 |

| 干球温度 T | ℃；开尔文输入显式减 273.15 | 冷却、配套响应 |

| 相对湿度 RH 或露点 Td | 0<RH≤100%；露点以 ℃ 计 | RH 转换露点后进入冷却响应 |



同一设备与需求情境放到不同网格时，温湿度进入冷却和配套计算；IT 资源路径按任务输入保持。缺失天气须补齐并登记处理依据。超出模型标定范围的小时保留外推标记。[6]



### 从观测窗口构造成全年



不满一年的任务序列按连续周/月重放，登记样本、日历映射、重复次数、相对起点和年末边界；保留跨小时、跨日期的作业。Lisa 时区需核实，ASI 没有实际日历；相对时钟的重放属于研究设定，缺少的季节变化保持未知。

年度电量 E=Σ_hP_h×1 小时，单位为 MWh；分别累计 IT、冷却、其他与设施总电量。年度 PUE=设施全年电量/IT 全年电量，峰值取最高小时平均功率。另报核心小时、GPU 小时和完成服务量。



### 每个情境应保存的结果



输出情境编号、网格、UTC 小时、两类资源份额、节点与卡数、IT 功率、散热、冷却、其他配套、设施总功率及外推标记，并形成月度/年度电量与峰值汇总。每条结果同时记录源文件、参数版本和实际使用的任务/气象时段。



## 5 柔性权限与控制变量



柔性权限作为独立的控制设计。基础情境固定为前面的 36 组；同一基础情境下，可以比较允许哪些控制操作。允许的操作范围由控制设置规定，启动时刻、运行状态和功率设定由求解过程选择。

| 控制设置 | 求解变量或执行路径 | 所需服务条件 |

| --- | --- | --- |

| 固定执行 | 保留历史启动和执行路径 | 作为同一业务与设备配置的参照 |

| 允许延后启动 | 每项作业的启动时刻 s_i | 数据就绪 r_i、完成期限 d_i、运行时长 p_i |

| 允许暂停与恢复 | 运行状态 x_i,t、暂停与恢复时刻 | 检查点、最小连续运行时间、恢复时长及额外能耗 |

| 允许调整功率或资源 | 功率上限、核心数或卡数 | 性能关系、最小并行规模、内存与服务质量 |





### 控制范围和可行性分别记录



任务类别用于确定研究中的候选范围。可延后上限、允许暂停的任务、检查点间隔和恢复开销单独登记；缺少实测权限时，明确写为控制设计假设。历史排队时长、训练标签或 LP 优先级不能单独给出新增延后额度。

固定资源、固定执行速度且连续运行时，作业满足 r_i≤s_i 且 s_i+p_i≤d_i，同时满足 CPU、GPU、内存和并行度约束。允许暂停时仍须完成所需运行量，并计入恢复开销；改变功率或资源时，需用相应性能关系约束完成工作量。



### 控制后重新计算负荷



每次求得新的执行路径，重新累计资源占用，并按第 3 节计算 IT、散热和冷却，再形成小时及年度总负荷。不同控制设置保持相同任务、完成要求、设备和气象条件，分别记录服务完成情况及负荷变化。

当前负荷模块接收给定资源路径；本章定义控制层的输入与约束，尚未完成这些控制变量与联合调度求解器的接入。

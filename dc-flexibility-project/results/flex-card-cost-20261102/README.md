# 需求侧柔性的成本：把卡计入后重算

用户 2026-11-02 指出：柔性要多配卡，卡闲置时也是成本，首版没有计入。本目录在 `flex-econ-copt-20261102` 的基础上把卡算进去，并按用户要求报告“在公允的发电和储能下做需求侧柔性，现在要花多少钱”。COPT 8.0.7，8 城市 × 11 情境（10MW），原生窗口。

## 口径

- **基线机群**：无柔性时按调度前任务功率峰值 K 配置，所需服务器台数 = 情境台数 × 利用率峰值（GPU 情境用 GPU 分配率，纯 CPU 型用 CPU 利用率代理；训练 0.926，云 0.599，其余 1.0）。有柔性和无柔性两种情况都用这批机器，它们的成本在差值里抵消。
- **加卡**：柔性要让某小时任务功率超过 K，就必须加卡，加多少由优化决定。新增卡的年化费用 = 服务器价 × 年化系数 0.332（8% 折现、4 年寿命，加 3% 运维）；新增卡全时开机待机，待机功率按情境“基础与空载 IT”每台的平均值计入设施用电。
- **服务器价**（情景假设）：纯 CPU 型 SR650 V3 双路 2 万美元（未取得报价）；CPU 主导型加 1 张 H100 PCIe，4.75 万；均衡型加 2 张，7.5 万；GPU 主导型 DGX H100 35 万（公开估计 30–45 万）。H100 PCIe 单卡按 2.75 万计（公开区间 2.2–3.2 万）。卡价另扫 0、0.1、0.3、1 倍。
- **柔性收益** = 无柔性总成本 − 有柔性总成本。总成本 = 能源系统（风光储、市电接入、电费、碳价）+ 新增卡年化（含待机耗电）。
- 推迟时长不变：可推迟·整体 12h，可推迟·可拆分 48h。其他成本参数同首版。

## 结果一：任何卡价下都不加卡

3,168 个“供给侧重新优化”的算例（`runs-cards.csv`）和 1,056 个“供给侧固定”的有柔性算例（`runs-fixed.csv`）中，按卡的市价计算时，新增卡全部为 0。卡免费、只计待机耗电时，最多也只加了 1.6 MW。原因有两个：

- 基线机群平均只用到 60–75%，峰值以下的空档已经够挪负荷。负荷挪进来的那个小时，这些卡本来就闲着；挪走的那个小时，它们又闲下来，卡的总使用时间不变，所以**峰值以内的柔性不需要额外硬件**。
- 要超出峰值就得加卡，加卡做柔性的单位成本远高于储能（见结果三）。

怎么读这张表：

- **峰值以内的柔性**：硬件成本为 0，每推迟 1 MWh 换来约 73–99 美元的能源节省（95% 时 32–75 美元）。这就是推迟本身（排队等待、存档恢复、服务承诺）能容忍的成本上限，超过它就不划算。以 GPU 主导型训练为例，每个已分配 GPU 的任务功率约 0.48 kW，1 MWh 约等于 2,100 GPU·小时，73 美元/MWh 相当于每推迟 1 GPU·小时约 0.035 美元。
- **加卡做柔性**：每推迟 1 MWh 要 5,800–35,000 美元（假设新增卡每天用 8 小时；每天只用 4 小时则翻倍），是储能（约 170–220 美元，100% 时 190–620 美元）的 30–170 倍。按 GPU·小时折算，训练约 4.7 美元/GPU·小时，和买一个 H100 小时的价格同一量级。
- 供给侧固定为 100% 无碳最优配置时，柔性没有可节省的空间（市电已经为 0，储能也已经建好），节省为 0。柔性在 100% 目标下的价值只有在供给侧重新优化、少建储能时才体现（见结果二）。

## 解释边界

- 服务器价是公开二手估计和量级假设，不是厂商报价；纯 CPU 服务器价格尚未核实。
- 新增卡按全时待机计耗电。如果能关机，待机耗电会小一些，但不改变量级结论（卡的年化费用占加卡柔性成本的 95% 以上）。
- 推迟和存档恢复本身的运营成本（排队等待、服务违约、存档开销）没有数据，只用能源收益给出可容忍的上限。
- 机群容量按任务功率峰值近似，没有逐卡约束；“可推迟·整体”仍未建模“开始后不可中断”。
- 固定供给侧的批次中，20 个无柔性对照算例（α=80–99%，COPT 状态 7）未求到最优解，相应配对已剔除，不计入中位数。

# 逐时无碳约束下卡价与机群规模敏感性

采用 [#65](https://github.com/TuzzyT-Laiii/33/pull/65) 冻结的八城市、九个 GPU 情境、任务量和 12/48 小时推迟期限。供能资产可重新规划。并列比较经济最优和 100% 逐时本地无碳供电，后者在模型中禁止购买市电。分析使用原设备成本假设做相对变化，基准设备成本属于研究输入。

## 比较方法

| 策略 | 设备规模 | 供能费用处理 |
| --- | --- | --- |
| 平卡 | 保留原台数 | 沿用相同任务柔性权限，采用已核验的供能费用区间 |
| 减卡 | 使用已证明可完成任务的最少台数 | 沿用有整作业连续约束的可行调度和供能费用下界 |
| 加卡 | 至少多一台服务器 | 先用供能费用下界判断所有更大机群能否胜过已核验的减卡方案 |

机群规模给定时，总年化成本为台数乘单台年化设备费，再加供能年化费用。卡价变化只改变设备成本项，给定台数和调度规则后可直接重计价格。整机价格取基准的 0.1、0.25、0.5、0.75、1、1.5、2 和 3 倍。单独改变 GPU 价格时保持其余部件价格不变，GPU 占基准整机价格的份额设为 50%、65%、80%，作为敏感性参数。GPU 报价倍率取 0、0.25、0.5、0.75、1、1.5、2 和 3。GPU 价格为零用于识别非 GPU 成本的下限。

平卡和减卡的价格交点等于减卡相对于平卡多出的供能年费除以基准价下少购设备的年化费用。因供能费用有上下界，交点也用区间表示。交点上界为保证减卡胜过平卡的充分条件，超过上界时可排除策略反转。负交点表示该区间相应端点下减卡供能也更便宜。

对加卡采用更宽松的比较。在原机群待机功耗下，放松逐小时 CPU/GPU 资源上限和整作业连续约束，求 12/48 小时期限制下的最优供能成本。任何增加台数的实际方案都可以放入这个放松后的任务可行域。增加的全时待机用电只会提高固定同一任务时序的供能费用，因此原台数的松弛供能费用也是加卡方案的下界。以至少加一台的年化设备费叠加该下界，与已核验的减卡可行方案比较。结果可证明一类容量策略被排除，不能识别低价区间的最优加卡数。原有按动态任务功率峰值决定是否加卡的扫描另列，保留模型区别。

## 卡价和运营冗余的二维敏感性

对 GPU 主导型训练、科研 AI 和推理，按最少可行台数的 0%、5% 和 10% 向上取整配置额外设备。额外设备作为备用，沿用同一套已核验的最少台数任务调度。对每个城市、供能目标及冗余比例重新优化风光储和市电，计入额外服务器的全时待机与随 PUE 变化的设施用电。然后用求出的供能费用重计每档卡价。该比较量化了保留冗余的成本，与允许备用设备参与常态调度的最优台数问题分别解释。

当价格落入交点区间，或备用要求使减配台数接近原台数时，需要针对该城市与任务重算容量选择。保持任务量和期限不变，在最少可行台数、带冗余的台数、原台数及其相邻整数台数优化供能和任务；只对尚无法排序的容量区间进一步收紧整数作业费用界限。价格点在区间两端和可能发生交叉的附近取值，各地保持相同气象及碳因子版本。该方法把新求解集中在会影响排序的价格和容量。

## 已计算的结果

- 经济最优情境下，保证减卡比平卡和所有加卡方案便宜的最高整机价格门槛是基准价的 **4.31%**。100% 本地无碳下最高为 **20.36%**，出现在阿什本的 GPU 主导型训练。整机价取基准的 0.25–3 倍时，两种目标的 144 个对照均可排除平卡和加卡。整机价降至 0.1 倍时，100% 无碳有 12 个对照的区间仍不能排除平卡或加卡。
- 单独改变 GPU 价格，其他部件保持基准价时，在三种 GPU 成本份额假设下，卡价取基准的 0.25–3 倍，均可排除平卡和加卡。GPU 免费的极端情景中，100% 无碳下 216 个城市、任务与成本份额组合有 215 个可确定减卡便宜，其余 1 个仍在区间内。
- 在 100% 本地无碳和基准价格下，GPU 主导型训练由 884 台增加到 973 台以保留 10% 冗余，额外待机使供能年费的八城市中位增量为 **53.8 万美元**，额外设备年费为 **1,034 万美元**。相同备用要求下，GPU 主导型推理由 1,121 台增加到原机群的 1,234 台，设备节省归零。
- 共重算 192 个供能问题，其中 48 个为推理的松弛下界，144 个为固定任务计划的供能优化。另核对并复用 96 个训练和科研 AI 的松弛下界。按原动态任务峰值口径复核 576 个已完成加卡扫描，观察到的新增算力均小于 10⁻⁶ MW。

## 复现和结果文件

1. 使用既有 COPT 环境运行 `analysis/cfe_card_price_energy.py`。按参数指定冻结的联合规划、任务、城市气象与容量证书目录，输出 `energy-cases.csv`。`reserve_grid_mwh` 为观测窗口市电用量，金额按窗口等效年化。
2. 运行 `analysis/report_cfe_card_price.py`。`--collected` 指向 #65 的 `collected-cities`，`--historic` 指向 `results/flex-card-cost-calendar-20261102/runs-cards.csv`，`--output` 指向含 `energy-cases.csv` 的结果目录。
3. `crossover-by-city.csv` 为逐城市交点和充分门槛，`price-sensitivity.csv` 为两类价格变化，`price-reserve-sensitivity.csv` 为冗余与价格组合，`historical-add-scan.csv` 为原生时钟加卡扫描核对。

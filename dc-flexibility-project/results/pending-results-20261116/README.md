# 柔性与推理收益的补充计算

这些计算对应结果框架中的持续调节、全球减配净收益、独立推理需求、供电价格和预测误差。金额沿用原稿的美元口径，窗口费用按实际观测小时数等效年化；归一化分母为同一地点、同一机群、不出售外部推理时的原参考年用电量。观测窗口年化不代表全年实测现金流。

供能优化沿用原时序估计的逐时 PUE，作为各调度情景的共同参数。任务调度或设备台数改变后的冷却负荷率反馈未进入该线性模型。

## 输入与可复现性

全球气象、设施用电和原价优化输入沿用 `global-flex-econ-20261103`；第三节需求和比较基线沿用 `residual-flex-global-20261114`。CPU/GPU 资源、整作业启动方案和台数证书来自 `minimum-server-capacity-20261108` 及其冻结的 `joint-compute-energy-20261107` 输入。这些来源分别对应 PR #80 和 PR #65；代码通过命令行参数显式指定其输入及分析目录。

`validation.json` 保存完整结果数量、输入结果文件校验值、约束残差和统计结果。完整逐格记录保留独立配对键，不以已经完成的部分网格估计全球中位数。

本目录归档全部 53,262 组减配记录、三档电价的逐格配对结果、各项统计表与 v18 Word。`provenance/delivery-validation.json` 记录稿件输入和输出校验值、13 个计算与审计程序统一 LF 换行后的校验值及九页版面核验；结果文件保留原始字节。原始电价求解记录和完整调度轨迹保留在研究服务器，完整文件校验值见 `validation.json`。

## 持续调节

`sustained_flexibility.py` 在 11 类机群的原生观测窗口中逐小时选择事件起点，分别求解 1、4、12、24 小时恒定削减功率。事件前保持原时序，事件内相对原小时任务功率恒定削减，事件后最多使用 48 小时恢复。整体小时工作量和可拆分工作量分别沿用 12、48 小时期限，所有到达工作量守恒，任务功率不超过原峰值；缺失观测时段不提供执行变量。

在最大削减功率下，第二次求解最小化恢复期相对原时序的额外功率峰值。记录同时包括事件转移电量、恢复期任务总功率峰值和额外补做峰值。这是第一节小时聚合功率模型的 IT 侧能力，未把聚合整体工作量解释为具有完整运行形状的逐作业保证。恢复数据不足的起点不进入统计。

完整结果有 170,284 个事件，约束残差最大为 9.26×10⁻¹⁰。三个真实机群中的八个事件使用 COPT 与 HiGHS 独立求解交叉核验。中位数描述观测起点的分布；存在零调节能力的起点时，不宣称该中位数能够随时交付。

## 全球减配与协同净收益

`global_pending_capacity.py` 对 4,842 个有效网格和 11 类机群逐一计算三项费用：原台数与原任务时序的最优供能；已核验完整任务调度及可行台数的最优供能；最少台数下界与放松资源、整体连续性后的供能费用下界。设备年化费用、整机待机功率和当地供能费用共同进入比较。

完整可行方案给出净收益下界，设备台数及供能费用的松弛给出净收益上界。这是联合规划最优净收益的有效包络；固定任务调度下的供能最优不能替代联合最优证明。HPC 主期限台数证书为 13,195–13,620 台，其他十类机群主期限台数已有一致上下界。服务器台数适用于冻结的小时资源投影，未包含显存、网络拓扑或逐秒资源装箱。

HPC、科研 AI 与推理共七类机群的原台数待机功率与原全球基准完全相同，可复用已核验的原价费用。5,598 组独立重算比较的最大差异为 3.73×10⁻⁹ 美元；云计算及训练使用实际台数对应的待机功率重新计算。

完整 53,262 组的可行方案净节省均为正，各机群中位数为 242–609 美元/MWh，设备贡献的中位数为 95.9%–98.1%。逐格最优收益区间宽度的各机群中位数为 4.80–53.73 美元/MWh，其中 HPC 的收益中位数上下界为 242–297 美元/MWh。供能约束最大残差为 5.09×10⁻¹¹；联合规划结果保留这些界限。

## 独立推理需求与设备服务能力

外部到达形状采用 [BurstGPT v2.0](https://github.com/HPMLL/BurstGPT/releases/tag/v2.0) 的前两批记录，由仓库已有的 `summarize_inference_requests.py` 合并并剔除首尾不完整自然日，得到 119 个完整观测日、5,252,477 次请求。请求计数保留输出为零的到达记录。原始文件校验值见 `data/metadata/inference-alternatives-20261031/server-download-manifest.json`，本次逐小时输入校验值记录于 `provenance/input-validation.json`。保留请求数量的日内变化和峰值，分别相对原任务窗口移动 0、24、168 小时；未循环复制为全年需求。计算仅使用两条曲线共同覆盖的观测小时，训练来源缺口内的请求量和可用容量均不进入该样本，不解释为已验证完整 119 日连续服务。

使用用户选定的公开 H100 基准：[NVIDIA TensorRT-LLM 性能表](https://nvidia.github.io/TensorRT-LLM/0.18.2/performance/perf-overview.html)。表中测量版本为 TensorRT-LLM 0.17，模型 Llama 3.1 8B，FP8，单张 H100 80GB HBM3、TP=1，输入及输出各 1,000 token，无限请求到达率和 in-flight batching。输出吞吐量 15,244.78 token/s 对应每 GPU 小时 54,881.208 个标准长度请求；敏感性使用该吞吐量的 25%、50%、100%。

公开吞吐量用于标准请求服务能力情景。BurstGPT 原记录的输入/输出 token 比为约 5.995，未将其原始 token 长度假装为基准的 1∶1。H100 PCIe 与 SXM 的实测延迟差异未由该单一基准消除；小时内完成也不等于已验证逐秒响应时限。

`resource_inference_capacity.py` 同时约束 CPU 和 GPU，小时时间转移保持各任务的 CPU/GPU 比例。外部服务的配套 CPU/GPU 需求比例沿用对应配置的 ASI 推理资源层，CPU 开销未由公开吞吐量表直接测得。`resource_inference_whole.py` 进一步允许完整作业在合法启动时刻之间重新安排，并保持其运行形状与整数作业数量。可行调度和松弛上界分别记录，差距小于 10⁻⁶ 的闲置量比例时记录为在该精度内得到容量证明。

在线请求须在到达小时完成；敏感性另设 28% 请求可在 24 小时内完成。该 28% 是服务情景设定，BurstGPT 本身没有给出这部分请求的离线标签。共同观测小时内的外部请求共用一个需求倍数，不按需求高低选择性剔除小时。承接比例以外部 GPU 小时除以需求覆盖期原始闲置 GPU 小时计算；吞吐量变化线性改变可承接标准请求数，不改变既定 CPU/GPU 时序下的占用比例。

`audit_inference_schedules.py` 从保存的完整作业安排重新累计 CPU/GPU 占用，独立核验整数数量、每组工作量、原任务资源守恒、设备容量和外部任务期限。已验证的混合服务方案去除外部离线执行后，其在线部分仍构成可行纯在线方案；程序独立核验这一构造后，才用于收紧纯在线容量的可行界。最终服务结果和审计文件通过 SHA-256 关联。

36 组完整作业调度全部通过独立核验，最大残差为 7.09×10⁻¹¹；162 行服务容量结果均达到上述最优性精度。在零相位、28% 请求可延后 24 小时的情景下，科研 AI、训练和推理的承接量分别约为原闲置 GPU 小时的 10.9%、26.2% 和 13.1%。25%、50%、100% 吞吐量下的可承接标准请求数按比例变化，已逐组核验。共同观测小时数为 1,903–2,856，随原任务用途和需求相位改变。

## 电价与 token 计价

`global_electricity_price.py` 在同一批网格分别计算基准、原机群协同和闲置 GPU 全部出售，在电价 0.5、1、1.5 倍下重新优化供能资产与调度。碳价保持原值。全部出售使用原时序实际闲置 GPU 数与原模型的任务电耗/GPU 小时换算，并验证既有 IT 功率容量。出售收入采用原稿 2.9 美元/GPU·时的固定研究价格；净收入扣除相对基准增加的最优供能费用。

原价基准与协同结果通过 `prepare_price_reference.py` 和独立重算核验后复用；检查原批次没有新增卡容量、配对键完整且无重复。电价求解使用同一组约束重新优化目标系数，逐个情景核验最优状态、资源平衡和变量上下界。

完整电价计算有 450,306 行结果，各机群的原生观测窗口内，原价协同节省的全球中位数为 3.54–15.73 美元/MWh。九类 GPU 机群在 0.5–1.5 倍电价下，全卖净收入的逐格变化中位数为 −0.37% 至 +0.57%，协同节省为 −37.10% 至 +34.33%。结果按同一参考用电量比较，最大约束残差为 1.99×10⁻¹⁰。

在 2.9 美元/GPU·时、闲置 GPU 全部售出的情景中，净收入的各机群全球中位数为 934–2,502 美元/MWh。43,578 个网格—GPU 机群组的全卖净收入均高于设备与供能联合规划净收益的松弛上界；逐格比值的各机群中位数为 1.97–5.33，全局最小值为 1.88。该比较要求全部闲置算力能够按给定价格售出，不代表独立真实需求已达到这一规模。

`audit_token_equivalent.py` 根据 [DeepSeek 的公开系统报告](https://github.com/deepseek-ai/open-infra-index/blob/main/202502OpenSourceWeek/day_6_one_more_thing_deepseekV3R1_inference_system_overview.md) 核算 2025-02-27 至 02-28 的 V3/R1 服务：平均 226.75 个八卡 H800 节点，共 43,536 GPU 小时；输入/输出 token 比约 3.619，输入缓存命中率约 56.25%。报告假设全部 token 按当时 R1 单价收费，理论收入 562,027 美元，对应每占用 H800 小时 12.909 美元；以峰值部署 278 个节点的全天卡时为分母则为 10.530 美元。该来源明确说明实际收入更低，因此此项为特定历史服务组合的理论毛收入参考。

## 滚动预测检验

`rolling_forecast_validation.py` 使用八城市对应的有效全球网格、11 类机群、需求上限的 50% 和 75%，共 176 组比较。风光及推理到达采用原真实输入。每小时以当前时隙及随后 48 个可观测时隙为窗口重新调度，当前小时已实现的需求与出力可见，未来采用前一日对应时刻最近可用的历史值；该时刻缺少观测时使用更早的最近观测。没有历史观测的起点使用当前值。时间缺口按真实经过小时处理，预测索引不能读取未来观测。

任务负荷、光伏与风电分别记录加权绝对百分比误差（WAPE）：对各滚动窗口内的全部未来预测点，累计绝对误差除以对应实际量之和。当前已观测时隙不进入预测误差统计，任务负荷包含原任务及外部推理，不包含固定待机功率。

每组同时回放顺序调度与协同调度，以及相同滚动窗口下的完全预知控制，使用各自原比较方案的固定风光储能资产和同样的初始空电池。电网接入允许按原模型单价增配，费用按实现的最高进口功率计入。最优化先减少预测到期欠账，再优化供能费用。

滚动窗口末，每类积压不超过同一预测下按最早期限立即执行的参考方案。协同模式显式加入该约束；顺序模式固定全部任务执行变量，窗口末积压由工作量守恒式确定，并逐步核验这一恒等式。最终完全预知控制的 176 组均按时完成，352 条顺序调度对照与参考费用完全一致，其中 20 条经独立全时段回放核验；相应输入与结果通过校验值关联。

行末积压只允许保留到下一可观测时刻仍未超过期限的工作量。三个训练输入各有 53 处观测缺口，其余八类机群时间轴连续；33 项任务层检查与上游真实时间期限函数一致。`finalize_forecast_results.py` 核对全部情景的输入、工作量守恒和对照结果，并保存 176 组最终文件的校验值。

实际执行保留原任务和外部离线任务队列，分别核验到达、执行和未完成工作量守恒。逾期比例以相关可推迟任务电量为分母，每份工作量首次逾期时计数一次；它不等于逐作业数量违约率。未完成工作的配对情景不计算可兑现节省，存在逾期的情景不进入按时交付收益统计。额外供能费用相对相同滚动窗口和初始状态的完全预知控制计算；实施费用与实际 SLA 赔偿尚无金额输入，不计入供能侧收益。

需求为上限 50% 时，88 对中有 40 对按时交付，其中 39 对节省为正，按时样本节省中位数为 4.85 美元/MWh，最小值为 −0.66；9 对完成但逾期，39 对在窗口末仍有未完成工作。需求为上限 75% 时，31 对按时交付且全部节省为正，中位数 4.16 美元/MWh；10 对完成但逾期，47 对仍有未完成工作。按时样本相对完全预知滚动控制的额外供能成本中位数分别为 1.92 和 1.98 美元/MWh。

两档需求下，协同调度逾期工作量占可推迟任务电量的中位数分别为 0.0003% 和 0.0069%，最大值分别为 2.28% 和 3.87%。前一日预测的任务、光伏与风电 WAPE 中位数分别为 15.4%、32.3% 和 100.9%。这些结果适用于该预测方法与八城市样本；全球正节省结论以完全预知条件界定。

## 执行入口

运行脚本需要 NumPy、pandas、PyArrow、SciPy 和 COPT，以及有效 COPT 许可。使用原冻结输入，进程数通过各脚本的 `--workers` 指定。`--project` 指向全球项目目录，`--joint` 指向冻结资源项目，`--capacity` 指向台数证书项目，`--residual-code` 指向第三节分析目录。

顺序为：持续调节、全球减配、电价、独立需求和滚动检验分别计算；独立需求依次运行小时耦合模型、完整作业模型和独立调度审计；滚动回放通过真实时间期限核验后汇总。所有结果齐全后运行 `report_pending_results.py --input RUN_ROOT --gpu RUN_ROOT/gpu-service-verified/gpu-service-capacity.csv --output REPORT_DIR`。汇总程序对覆盖数量、配对键、约束残差、审计校验值与工作量守恒执行强制检查。

## 1 五种配置及其研究基本单元

C20/C21/C22/C28 按完整服务器计数；R-GB200 按 GB200 NVL72 整柜计数。R 表示 rack，避免将整柜误读为单台服务器。SR650 V3 为 2U、DGX H100 为 8U；U 表示机架内设备的高度单位。[1,2,11,12]

| 情境 | CPU∶GPU | 参考平台 | 证据性质 |

| --- | --- | --- | --- |

| C20：纯 CPU | 2∶0 / 台 | 双路 SR650 V3，不装计算 GPU | 厂商支持的双路 6448Y 选配 [1] |

| C21：CPU 数量较多 | 2 CPU∶1 GPU | 双路 SR650 V3＋1 张 H100 PCIe | 从厂商支持选件与插槽规则中选取 [1] |

| C22：两类数量相等 | 2 CPU∶2 GPU | 双路 SR650 V3＋2 张 H100 PCIe | 厂商明确列出两卡位置及温度条件 [1] |

| C28：GPU 数量较多 | 2∶8 / 台 | DGX H100：2 颗 Xeon 8480C＋8 张 H100 | 官方固定整机配置 [2] |

| R-GB200：基本纯 GPU | 36∶72 / 柜 | GB200 NVL72，Grace＋Blackwell | NVIDIA 官方整柜架构 [11-14] |

CPU 按物理处理器封装计，GPU 按计算卡或加速器模块计。管理控制器的集成显示不计入计算 GPU；机柜 DPU、BMC 和交换管理处理器不计入 36 颗 Grace 主机 CPU。数量、算力、功率及全年电量分别核算。

GPU 服务器需要宿主 CPU。‘基本纯 GPU’按 CPU 仅承担主机及 GPU 配套工作、电耗以 GPU 为主的研究形态定义；实际功率份额仍待测量，不能从 36∶72 推算。不同配置的处理器、互联及冷却差异同时保留，比较结果按完整架构解释。

MW 表示完整参考 IT 预算。配置按允许需求配对，scenario_id 沿用‘规模MW_配置编号_来源首词小写’，例如 1MW_C20_lisa、1MW_C20_alibaba、1MW_R-GB200_acme；原有 36 个标识保留。各基本单元的数量根据分配预算与对应完整单元参考功率换算。

### 同台 CPU/GPU 的联合响应

对配置 k，读取对应硬件的整机响应 p_k(u_CPU,h,u_GPU,h)，保留同一时段 CPU、GPU、内存及任务关系。p_k 已包含整机所有被测组件；CPU 颗数与 GPU 数量用于定义设备和资源上限。

记基本单元预算为 S_unit≤S，数量 N_k=floor(S_unit×10<sup>6</sup>/p_k,ref)。小时功率 P_unit,h=N_k p_k(u_CPU,h,u_GPU,h)/10<sup>6</sup>。CPU 总颗数=a_kN_k、核心数=c_kN_k、GPU 数量=g_kN_k；a/c/g 读取每个 per_unit 参数。C20 的 g=0；R-GB200 每单元为整柜的 36/2592/72。

完整服务器功率包含 CPU、GPU、内存、主板、机内存储、网卡、风扇和电源转换损耗；这些部分随整机计入 IT。机房冷却设备的耗电在设施侧单独计算。

不同 CPU/GPU 型号需要对应性能与功率标定；PCIe 与 SXM 卡也保留不同硬件标识。增加 GPU 数量会改变互联、内存、风扇和任务性能，整机功率不能仅由卡数比推算。

### 散热、温湿度与全年结果

公共网络和独立存储的 IT 功率按清单另加，得到 P_IT,h。散热需求 Q_h≈P_IT,h；使用当地逐小时温度及露点/相对湿度、冷却技术参数计算 P_cool,h，再形成 P_fac,h=P_IT,h+P_cool,h+P_other,h。

五类配置均需匹配的完整单元功率曲线，台数/柜数、总 CPU/GPU 数量和功率份额留空。DGX H100 的 10.2 kW 为最大铭牌，GB200 约 120 kW 为官方近似整柜描述；二者均不作为运行参考功率。既有 8.43 kW 实测属于另一台 AMD HGX 节点。[2,4,12]

### ASI 的具体作用

ASI 补充生产运营中的业务构成与小时变化，提供归属 GPU 小时、服务器 GPU 库存、CPU 容量与请求利用率等字段；也能按高/低优先级区分候选任务。它不直接给出 CPU 物理插槽数量、逐任务允许延期时间或抢占许可。

因此，ASI 用于选择生产需求路径和柔性候选范围；单机 2∶1、2∶2、2∶8 的设备参数来自厂商配置。任务类型、历史低优先级和小时归属量分别保留其来源含义。

已有 ASI 单日重复 365 次形成的年曲线属于方法演示，不能据此判断全年生产业务的季节变化。Lisa、Acme、ASI 是本工作区已经详细核验的三套主样本；其他公开数据按其适用问题单独评估。

## 7 8760 小时生成规则与已有结果

源任务先按真实运行区间积分，得到同一时刻的 CPU 核心小时、GPU 小时或利用率；确认同机联合需求后，使用相同的时间映射扩展两条路径。不能把互不对应的独立 CPU 业务曲线直接当成 GPU 服务器的宿主占用。

| 现有源窗口 | 2025 年 8760 小时的重放方法 | 说明 |

| --- | --- | --- |

| Lisa 309 日 | 1 个完整窗口＋前 56 日 | 保留连续资源形状，样本外季节性未知 |

| Acme 90 日 | 4 个完整窗口＋前 5 日 | CPU/GPU 同相位映射，保留业务关系 |

| ASI 1 日 | 同一天重复 365 次 | 方法演示，跨日变化未识别 |

规则为 j(h)=(h+φ) mod L；H=8760（平年）或 8784（闰年）。保存每小时源索引、循环边界与起始相位；使用目标年逐小时天气重新计算冷却。年电量 E=Σ_hP_h×1 小时，年度 PUE=ΣP_fac/ΣP_IT。

已有 20261026-v2 年度报告提供 16 条、140160 条小时负荷记录及 490 组相位检查。它们属于既有纯设备池参考模型，与本说明五类配置分别保存。新版年曲线需要联合需求、完整单元功率标定，以及适用的冷却参数。

本次交付为五类实际配置的参数表和 52 个设计单元，未计算新年曲线。Alibaba 2018 尚未下载，不设置其年度重放长度。旧版 20261027 的全部文件 SHA-256 逐一核对并保持原样。

## 8 冷却方式与气象耦合待办

scenario-matrix 的每个单元显式保存 cooling_type：C20/C21/C22/C28 为 air（44 个单元），R-GB200 为 direct_liquid（8 个单元）。现有冷却/气象耦合模块按风冷机房设计，GB200 必须另建并验证液冷参数。本次仅登记待办，未实现新冷却模型。

GB200 的液体经过冷板直接冷却 CPU/GPU，部分网络、存储和电源部件仍需风冷。因此 direct_liquid 表示主要芯片采用直接液冷，残余风冷热负荷仍需纳入设施计量。[12,13]

| 待办 | 需要核定的内容 |

| --- | --- |

| 供液与换热边界 | 相较风冷机房可采用更高供液温度；实际供回液温度、流量及换热效率须有官方规格或测量依据 |

| 干冷器与冷却塔 | 干冷器主要受干球温度影响，蒸发冷却塔受湿球温度影响；按实际散热方案建立不同气象响应 |

| 冷却电功率 | 分别核定 CDU、泵、风机、残余风冷及可能的机械制冷功率，避免与整柜 IT 重复计量 |

| 校准与验证 | 核对整柜工作负载、供液条件、气象覆盖和适用范围；取得数据后验证独立参数 |

本次供液温度、流量、热量液冷份额、COP/PUE 和气象响应系数均未赋值。GB200 单元的 cooling_model_status 明确为待建独立液冷耦合；不能直接应用现有风冷机房系数输出其设施负荷。

## 9 柔性权限与控制设计

柔性权限独立于规模、单机数量配置和需求导向。对同一任务集合，可以设置固定执行、允许延后启动、允许暂停恢复或允许调整功率/资源的控制范围。

| 控制设置 | 需要的依据 | 求解后重新计算 |

| --- | --- | --- |

| 延后启动 | 数据就绪、完成期限、运行时长和依赖 | CPU/GPU 同时占用及资源约束 |

| 暂停与恢复 | 检查点、最小连续运行、恢复时长和额外能耗 | 完整运行量与恢复开销 |

| 调整功率或资源 | 设备与任务的性能关系、最小并行度、内存和服务时延 | 完成工作量、功率和冷却 |

训练、推理、CPU 标签和任务优先级支持候选分类；可延期时长和暂停权限按实际服务约束或明确的控制设计填写，未知值保留为空。

在同一服务器上，CPU 与 GPU 可能共同参与一项任务，不能将其独立平移到互不对应的小时。调度改变执行路径后，重新计算联合资源、整机 IT、散热与气象相关冷却。

本次交付为服务器与整柜配置情境及参数说明，未求解任务级全年调度或确认新增的业务权限。

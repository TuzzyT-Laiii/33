# 八城市算力与供能联合规划

按八城市、11 个 10 MW 参考任务情境以及 2025 年气象，比较三个新建系统对照。A 使用原始时序和满足该时序的最少整机台数。B 固定 A 的台数，允许重排任务。C 同时优化任务和整数整机台数，台数上限为 A。三组均优化风、光、储能功率和电量、市电接入及逐时供电。

容量由 CPU 和 GPU 两种小时资源需求分别限制，GPU 数按同情境每台装卡数换算。负荷在目标硬件上的换算沿用已审计的 10 MW 参考情境。整机价格采用已有成本情境，设备费按 8% 折现率、4 年寿命及 3% 固定运维年化。基础与空载功率按整机台数调整，冷却使用相同城市小时气象系数。设施用电和购电费用按原生观测小时计入，经济结果以等效年化形式报告。

## 任务与可行域

- 刚性、未知及缺少相匹配作业记录的负荷固定。云通用计算和推理在本批次沿用原小时负荷时序。
- 可拆分批次按来源小时分组，在到达后 48 个经过小时内分配。一个批次的 CPU、GPU 和动态 IT 用电按同一比例转移。
- Lisa 科研分区、MIT 选定的批处理和 Seren 评测作业采用原记录的起止时间。以相同起止小时为组选择一次平移，组内作业完整运行，最大平移 12 个经过小时。原始或目标区间跨未观测小时的作业组合不进入可移选项。相同起止小时采用共同平移是为缩小整数问题的可行域限制。
- 逐小时资源约束采用设备等效量，适用于同机型情境内的相对规划。逐节点装箱、显存、拓扑、业务授权和检查点代价仍需现场证据。

## 输出与验收

逐算例记录求解状态、设备台数、设备采购额、等效年化设备和能源成本。非最优终止时保留已通过约束检查的可行解及目标函数下界。比较程序独立核对共同输入哈希、台数关系、成本拆分和嵌套对照，再输出 B 至 C 净节省的上下界。能确认的覆盖采用“已找到减配可行解且净节省下界为正”。

每个算例使用一个求解线程，各情境并行，并复用本情境的调度矩阵。C 使用 B 的可行解作为求解起点，`--capacity-start` 还可先固定整体作业选择，快速取得容量更小的起点。后续算例的 MIP 相对差距容差为 0.01%，已完成算例保留各自的解与成本界限。

## 复现入口

- `analysis/joint_capacity_inputs.py prepare` 从冻结的源时序和城市输入核对任务小时并建立基准机群清单。
- `analysis/joint_capacity_whole_jobs.py` 按源数据清单核对 Lisa、MIT 和 Seren 作业文件，重建可整体移动的作业负荷。原始和逐作业派生数据留在原授权存储。
- `analysis/joint_capacity_inputs.py baseline` 求解 A，`analysis/joint_capacity_copt.py` 求解 B、C。使用 `--target economic` 与 `--target alpha100` 分别运行两种供能设定。支持按城市和情境选择组合。
- `analysis/report_joint_capacity.py` 从各组 JSON 生成配对表及逐阶段状态统计。
